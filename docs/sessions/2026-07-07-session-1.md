## 关键决策

1. **范围收缩**：放弃 Java/Python，只做 C
2. **主角维度选择**：治理与护栏（理由：教学场景下"不主动改代码"是核心 feature）
3. **技术栈**：Python 3.11 + OpenAI SDK + FastAPI + keyring
4. **沙箱实现**：进程级（subprocess + ulimit + env 清理），不引入 Docker
5. **HITL 状态机**：二维状态机（Cursor agent mode 风格）
6. **TDD 严格**：每个 task = 红 + 绿 + 重构，3 个独立 commit
7. **MockLLM 优先**：所有 CI 测试用 mock，**不依赖网络/真 LLM**
8. **凭据管理**：keyring 主方案 + .env fallback + env var 最后手段

## 学到的教训

- **L1（编码协作）**：当用户说"看不到"时，先用 `git status` + `git diff --stat` 检查是否有未保存修改，再下结论
- **L2（SPEC 写作）**：明确章节编号 + commit message 写明章节
- **L3（工作流）**：项目级 `AGENTS.md` 必须尽早写——它是 cross-session context 的"重启文件"

- **L5（plan 写作）**：分块写入比单次 write 大文件更稳
- **L6（spec vs plan）**：spec 14 章 vs plan 18 task 是合理映射
